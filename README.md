# Przepływ krytyczny

Interaktywna gra decyzyjna o komunikacji, automatyzacji i odporności zespołu.

W ciągu pięciu dni gracz decyduje, kto ma prawo podejmować decyzje, gdzie wprowadzić AI, kiedy potrzebna jest kontrola człowieka i jak zareagować na awarię. Każdy wybór od razu zmienia co najmniej dwa parametry zespołu, a część decyzji wraca później jako konsekwencja.

## Uruchomienie

Nie potrzebujesz instalacji, npm ani serwera. Otwórz `index.html` dwuklikiem.

## Co sprawdza gra

Gra łączy przepływ informacji, strukturę odpowiedzialności i automatyzację. AI nie jest premią do wyniku: może zwiększyć przepustowość, ale źle umieszczone w procesie powiększa koszt błędu. Centralizacja może z kolei przyspieszyć pracę krótkoterminowo, a później obniżyć odporność zespołu.

## Mechanika

- pięć dni rozwijającego się kryzysu
- cztery decyzje w każdym dniu
- natychmiastowe zmiany parametrów i opis konsekwencji
- odroczone skutki wcześniejszych wyborów
- zmieniający się przepływ informacji
- quizy diagnostyczne
- osiągnięcia
- kilka wariantów podsumowania
- możliwość ponownego przejścia inną strategią

## Parametry

Zaufanie, przepustowość, jakość decyzji, obciążenie ludzi i dług procesowy.

## Technologie

HTML, CSS i vanilla JavaScript. Projekt jest samodzielnym statycznym plikiem i nadaje się do GitHub Pages.

## Responsywność

Interfejs został sprawdzony przy szerokościach 320, 768 i 1440 px, ze szczególnym uwzględnieniem dłuższego polskiego microcopy.

## Założenie językowe

Gra nie wymaga znajomości prawa Conwaya ani terminologii z obszaru projektowania systemów. Mechanizmy są wyjaśniane przez sytuacje i konsekwencje: gracz widzi, gdzie zatrzymuje się informacja, co dzieje się po centralizacji decyzji oraz kiedy automatyzacja potrzebuje kontroli człowieka.
